# 要求に基づく生成メッシュから全周参照とGSを作る実装 v10

2026-10-23。v8の「検出した正面の物体を手続き的部品にし、形状を固定してGSへ符号化する」方式を改め、LLMと学習済み物体メッシュ生成を接続した。

## 構成と変更箇所

| ファイル | 実装内容 |
|---|---|
| `worldgs/semantic_plan.py` | ローカルLLMから物体ごとのID・数量・説明・寸法・配置関係・材質・照明・要求台帳をJSON化。LLMの要求監査と、数値的な室内境界・衝突・接地・相対配置検査を組み合わせる。 |
| `worldgs/learned_scene.py` | 段階実行と再開、物体画像生成、専用環境呼び出し、UV付きメッシュの組み立て、撮影計画を統括。 |
| `worldgs/asset_worker.py` | SAM3で画像内の対象だけを抽出し、SAM 3DでUVテクスチャ付きメッシュを生成。別環境の別プロセスで実行し、失敗時は代替形状を出さず停止。 |
| `worldgs/physical_render.py` | 同じ生成メッシュ群・UV・材質・照明をBlender Cyclesで多視点描画。OpenCVとBlenderの座標変換を明示する。 |
| `worldgs/learned_references.py` | 同じ三角形から深度・法線・IDを取得し、物理描画のRGBで面上の初期点を着色。学習・評価カメラを分離。 |
| `worldgs/train_mesh.py` | 位置・回転・スケール・色・不透明度を学習し、分割・削除を行う。構造面との距離・厚みの弱い制約を追加。マットな塗り壁・天井はSH0で扱い、不必要な視点依存色を抑える。 |
| `worldgs/cli.py`, `pipeline.py`, `train.py` | 既定の`learned`方式、`plan`単体実行、`--resume`、形式に応じた学習の分岐と段階状態を追加。 |
| `tests/test_learned_scene.py` | 任意カテゴリのデータ処理、衝突補正、物体方向に基づく前後関係、座標変換、生成形状の比率保持・接地、隅のカメラ、バックエンド失敗時の停止、既定経路を検査。 |

```text
プロンプト
  → 要求台帳＋シーングラフ（LLM）
  → 配置の数値補正と要求監査
  → 物体ごとの画像候補
  → SAM3の物体マスク
  → SAM 3DのUV付き生成メッシュ
  → 尺度・向きの正規化と配置の再検査
  → 照明・材質付き全周RGB＋直接取得した深度・法線・ID
  → 面上の参照点
  → 自由度を持つ3DGS最適化
```

## 正面画像依存と箱への置き換えを廃止

物体一覧は画像検出ではなくプロンプトから先に決める。現在の計画器はQwen2.5-3B-Instructで、v9の3家具に限定した単語解析ではない。正面に写らない物体も個別の画像とメッシュを生成する。画像が切れている・マスクがない・メッシュが生成できない場合は成功扱いにしない。

画像に複数の物体が含まれた場合も、SAM3で採用した1つの対象のマスクだけをSAM 3Dへ渡す。他の物体はマスクの外側に置く。候補・採用画像・マスク・検出信頼度を保存する。

SAM 3DのGLBをカメラ系のy下向き座標へ変換し、均一倍率で尺度を合わせる。非等方拡大で家具を箱の寸法へ押し込めない。言語モデルの寸法は不確実な事前値として扱い、生成形状の比率を保った実寸法で配置・衝突を再検査する。明示的な数値寸法要求は`size_locked`として扱い、比率を保ったまま許容差を満たせない場合は停止する。

## 写実的な多視点参照の作り方

物体画像から生成したUVテクスチャを実メッシュに保持し、床材とPBRの塗り壁・天井、面光源による照明・影を同じBlenderシーンで描画する。この段階では視点ごとの拡散画像補完を使わない。窓などの立体要素が2D画像だけに増える問題を避け、RGBと深度が同じ幾何に対応するようにした。多視点拡散による追加の外観リファインは今回の実装には含めていない。

深度はメッシュとの交差から求めるカメラz値。全周参照画像から単眼深度を再推定しない。ただしSAM 3D内部では物体画像からの形状・深度推論を利用しており、その推定誤差までなくなるわけではない。

カメラは水平360°、上下向き、家具周囲、部屋の隅、移動した垂直上下方向を組み合わせる。隅の観測が不足すると、メッシュが閉じていても参照点が欠けるため、構造用の追加カメラは学習用に保持する。元の評価カメラはGS学習から除外する。

## GSの自由度と構造の保持

メッシュ面上に重心座標で初期点を置き、位置・回転・3軸スケール・不透明度・SH色を最適化する。面への強制射影はしない。

- 直接描画した深度の損失係数は0.2。
- 構造との距離・厚みなどの弱い制約の係数は0.3。部屋構造の距離許容は0.015、家具は0.06シーン単位。
- 既知面の被覆損失係数は0.05。
- 初期サイズは近傍6点の平均距離から求め、面を覆う重なりを持たせる。法線方向は初期化時に薄くするが、学習中は固定しない。
- マットな塗り壁・天井の高次SHを無効にし、局所的な基準色への弱い損失を使う。家具・床のSH3と形状は学習できる。

日本語の「ベッド1台・木製椅子2脚・椅子をベッドの隣」の計画も生成し、物体数と近接距離を検査した。こちらは計画段階の追加検証で、ベッドルームのメッシュ化・GS学習を完走したという意味ではない。

## このPCで必要だった実行環境の切り分け

- 主環境：`~/.venvs/world-gs`。PyTorch 2.7.1+cu128、gsplat、RTX 5070 Ti。
- 分割：`worldmesh-sam3`。専用のCUDA 13ライブラリをそのプロセス内で探索するようにした。
- 3D生成：`worldmesh-sam3d-objects`。別の`-sm120`環境はPyTorch3Dのバイナリ不一致があったため使用しない。採用環境ではPyTorch3DのCUDA描画まで実行確認した。
- SAM 3Dコード：既存の`worldmesh-main-optimized/sam-3d-objects`を明示して読み込む。低VRAM時の重み退避を使い、DINOの非対応xformers経路は無効にする。
- Blender：5.1.2。今回のCycles描画はCPU、32サンプル。GPUの選択に成功した環境ではOptiXを使用する。

公式SAM 3Dの標準セットアップ条件と、このPCの低VRAM調整済み環境は区別する。外部環境は上書き再インストールせず、`WORLDGS_SAM3D_ROOT`, `WORLDGS_SAM3_PYTHON`, `WORLDGS_SAM3D_PYTHON`, `WORLDGS_BLENDER`で指定できる。

## 確認する出力

- `planning/scene_plan.json`：要求台帳と計画、補正、LLM検査。
- `assets/*/generated.glb`：生成メッシュの原形。`placed.glb`：配置後。
- `scene_mesh.glb`, `meshes/*.glb`：全体と部屋・家具群。
- `physical_scene.blend`：照明・材質・全参照カメラを確認できるシーン。
- `references.jpg`, `heldout_references.jpg`：全周参照。
- `scene_unity.ply`：Unityへ読み込む結果。
- `validation_preview.png`：基準描画と実際のGSの比較画像。`heldout_preview.png`：評価視点の比較。
- `verification.json`, `training.json`, `evaluation.json`：検査と学習記録。

生成データはWSLの`runs/`に保存し、コード・文書をGitHubに保存する。Unityエディター上での読み込み操作・描画確認は今回行っていない。

## 残る制約

対象は単一の矩形室内と床支持の物体。複数部屋、開口、天井吊り、積み重ねなどは別の配置・支持関係・描画処理が必要。未対応要求は停止する設計だが、自然言語の監査自体が完全とは限らない。

生成器は見えない背面や細部を推測し、寸法は名目上の事前値である。生成UVには照明が混ざる場合があり、厳密な反射率ではない。GSの細部のぼけ・色むら、推定形状の誤りは残る。照明はGSへ焼き込まれるため、Unityの動的ライトへ反応する再照明方式は実装していない。

モデルの公式資料：[Qwen2.5-3B-Instruct](https://huggingface.co/Qwen/Qwen2.5-3B-Instruct)、[SAM3](https://github.com/facebookresearch/sam3)、[SAM 3D Objects](https://github.com/facebookresearch/sam-3d-objects)、[SAM 3Dセットアップ](https://github.com/facebookresearch/sam-3d-objects/blob/main/doc/setup.md)。本実装の検証値は、このリポジトリの実行結果に基づく。
