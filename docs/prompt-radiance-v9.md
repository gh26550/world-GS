# プロンプトからの全体構成と写実的参照の試作v9

これは旧試作の記録です。後続の[v10](learned-v10.md)でLLM計画・SAM 3D・物理描画を接続しています。

## 前回の問題

v8は正面画像から検出した物体だけを近似部品に置き換え、簡易材質で描画した画像をGSに学習させていた。これでは、正面に写らない要求物体が抜け、外観も簡易メッシュの描画品質に制限される。さらにガウスの全形状パラメータを固定したため、GSは外観の符号化に留まっていた。これは目標である「プロンプトの要件を満たす粗い空間から、多視点を使って写実的なGSを生成する」構成の完成形ではない。

## 追加した処理

1. `scene_plan.py`で正面画像を見る前に明示された物体と個数を登録する。現在はソファ・本棚・テーブルに限定した語彙・個数の解析と配置規則。汎用LLMによる意味理解は実装していない。配置規則には衝突検査があり、対応を実装していない既知の家具語はエラーにする。
2. `mesh_scene.py`でソファの座面・背・肘・脚、棚板・支柱・本、机の天板・脚を作り、計画された位置と向きへ配置する。画像に見えなかった物体を検出結果で削除しない。
3. `prompt_scene.py`でメッシュから全周の深度とカメラを取得し、ControlNet深度条件付き画像補完を行う。視点ごとの深度再推定と形状パッチの追加は行わない。
4. `surface_appearance.py`に三角形ごとの外観メモリを持ち、生成色を3D表面へ記録する。後の視点へ再投影し、既知の色を保持する。学習用参照は全て最終的な同じ外観メモリから再描画する。評価用カメラは外観の生成・更新に使用しない。
5. `train_mesh.py`で位置・回転・3軸スケール・不透明度・SH色の学習と分割を戻す。メッシュは初期化と弱い構造制約に使用する。構造面からの距離・厚みへのペナルティと、メッシュから直接描画した深度による損失を使う。強制的な面への射影や位置固定はしない。

`train.py`で新形式へ分岐し、`cli.py`と`pipeline.py`へ実験用の`--mode scene`を追加した。v9は目視で画質上の問題が確認されたため既定へ昇格していない。v8と過去の出力は維持する。

## 実験の実行方法

```bash
cd '/home/dpc7/world GS'
./run.sh generate --mode scene --prompt 'A cozy living room with a sofa, bookshelves and a wooden table, wide angle interior photograph' --output runs/prompt_scene_experiment --size 384 --views 12 --seed 42
./run.sh train runs/prompt_scene_experiment --steps 2000 --max-points 100000
```

このコマンドは試作を再現するもので、完成品質を保証しない。対応する家具語がない場合や、把握できる未対応家具を要求した場合は停止する。任意の空間関係・部屋形状・家具カテゴリを解釈する仕組みはない。単語解析で把握できない要件を全て検出できるわけでもない。メタデータは`experimental=true`, `general_prompt_compliance_verified=false`として保存する。

## 実測と目視

実行先は`runs/livingroom_prompt_radiance_v9`。既存画像・検出結果を使わず、プロンプトから実行した。

- 要求と実際の物体メッシュ：ソファ1台、本棚2台、テーブル1台。各物体は独立した部品群。
- 73視点（学習58、評価15）、384px。2,000ステップ、初期100,000から最終180,000ガウス。
- 全6種類のパラメータ（位置、回転、スケール、不透明度、SH0、SH1〜3）が学習対象。
- 10,000個を無作為抽出したガウス中心から実メッシュ面への距離は中央値約0.0116、95パーセンタイル約0.0181シーン単位。
- 同じメッシュと外観から描画した評価参照に対する平均相対深度誤差は約0.99%。独立した実写への精度ではない。
- 63件の自動テスト成功。物体登録、個数、未対応語での停止、立体部品と回転、共有外観の保持、全参照の深度・カメラ整合を検査。

**目視では未合格。** 正面の提案画像には写真らしい外観が戻ったが、斜め方向・上下方向ではテクスチャの伸び、投影跡、継ぎ目が残る。生成された窓や背景がメッシュ上の開口・立体構造を伴わない問題もある。低い深度損失は、粗いメッシュと合うことを示すだけで、写実性やプロンプト全体への適合を保証しない。出力の`verification.json`に`accepted_for_production=false`と目視所見を記録した。

確認するファイル：

- `scene_plan.json`：認識した要求、物体数、配置、計画器の制限。
- `scene_mesh.glb`, `meshes/*.obj`：簡易な形状ガイド。
- `style_front.png`：プロンプトから生成した最初のスタイル画像。配置の決定には使わない。
- `appearance_keyframes/proposal_*.png`：深度条件付き画像生成の提案とマスク。
- `surface_appearance.npz`：3D表面に対応する共有色。
- `references.jpg`, `heldout_references.jpg`：同じ表面メモリから描画した学習・評価参照。
- `scene_unity.ply`, `heldout_preview.png`：GSと未学習視点の描画比較。
- `verification.json`, `appearance_report.json`：内部整合検査と未達事項。

## 目標の達成にまだ必要な処理

- **意味的な計画器**：プロンプトから物体・数量・相対配置・材質・照明・部屋構造を扱うシーングラフを作り、要求ごとに充足を検査する。現状の限定的な単語解析と既定位置だけでは代替できない。
- **物体形状の生成または選択**：要求カテゴリに対応した3D資産・学習済みメッシュ生成器を使用する。現状は3種類の手続き的部品ライブラリであり、汎用のテキストから3D形状を生成するモデルではない。
- **形状と外観の整合**：生成した窓などの形状を伴う要素をシーングラフと幾何へ反映するか、画像側で拒否する必要がある。三角形への投影だけで形状を伴う要素を扱うと、画像を貼ったように見える。
- **多視点外観の最適化**：浅い角度からの低品質投影を固定せず、面の観測角度・解像度に応じた選択、UVの継ぎ目処理、視点間の生成整合を行う必要がある。

既存のローカル環境では、SAM 3D Objectsの約13GBのチェックポイントと専用Python環境が別プロジェクト内に見つかった。World-GSへの統合と、その環境での物体生成・向き・尺度・材質の検証はまだ行っていない。汎用の意味的計画器も未接続。これらの部分を実装・動作確認済みとは報告しない。
