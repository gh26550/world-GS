# メッシュを形状の基準にする構成への変更（2026-10-23）

## 処理の流れ

```text
プロンプト → 正面画像 → 物体検出・初期配置
                         ↓
                  部屋・家具のメッシュ群
                         ↓ 形状はここで固定
      水平方向360°＋高さを変えた上下視点＋家具周囲のカメラ
                         ↓
           RGB・直接描画した深度・法線・三角形ID
                         ↓
             メッシュ面上にガウスを配置
                         ↓
           中心・回転・スケールを保持し、色と不透明度を学習
```

正面画像の深度推定は家具配置の補助に一度だけ使用する。床・天井・壁の形状は部屋寸法から作り、ソファは座面・背面・肘・脚、机は天板・脚、棚は支柱・棚板・本の部品に分ける。これは手続き的な近似メッシュで、単眼画像から見えない背面まで復元する学習モデルではない。

旧expand方式のように、追加視点ごとに画像補完・深度推定して形状を追加しない。全カメラの深度は同じ三角形メッシュとの交差から得るカメラz値である。正面画像をそのまま壁に投影する処理も使わない。

## 変更したファイル

| ファイル | 変更内容 |
|---|---|
| `worldgs/cli.py`, `pipeline.py` | 既定を`mesh`へ変更。既存レイアウトを再利用する`--layout-file`を追加。旧expandは明示指定で保持。 |
| `worldgs/mesh_scene.py` | 水平360°の各方位に水平・上・下のカメラを配置。上下のカメラ位置と高さも変え、家具内部を避ける。家具周囲の撮影も追加。 |
| `worldgs/mesh_pipeline.py` | メッシュ群を保存後、同じ形状から全参照を描画。RGBに加え深度・世界座標法線・三角形IDを保存。学習用と評価用を分離。 |
| `worldgs/teacher_geometry.py` | 学習カメラから見える面を面積に応じてサンプリング。点と三角形の重心座標による対応、メッシュ識別情報、床・天井・壁の平面検査を追加。 |
| `worldgs/train.py`, `train_teacher.py` | v8専用の学習へ分岐。中心・回転・3軸スケールを固定し、不透明度・SH0〜3色を最適化。固定形状を壊す分割・移動は行わない。 |
| `tests/test_mesh_teacher.py` | 平面深度、上下カメラの移動、天井の変形検出、既定経路、点・参照深度の改変検出、深度推定なしのレイアウト再利用を検証。 |

ガウスは法線に沿う軸を薄くし、その標準偏差を最大0.006シーン単位に制限する。接線方向には面を覆う重なりを持たせる。学習するのは`opacities`, `sh0`, `shN`で、`means`, `quats`, `scales`は固定する。形状が基準から動かないことを優先した構成であり、RGBから細かな凹凸を学習する方式ではない。

学習前に、GLBとメッシュ配列の識別情報、面上の初期点、全参照の深度・カメラと対応三角形の整合を検査する。生成後にメッシュを差し替えた場合は参照を再生成する必要がある。単にPLYを再学習しても参照は更新されない。

## 実行例

```bash
cd '/home/dpc7/world GS'
./run.sh generate --prompt 'A cozy living room with a sofa, bookshelves and a wooden table, wide angle interior photograph' --output runs/livingroom_mesh_new --size 384 --views 12 --seed 42
./run.sh train runs/livingroom_mesh_new --steps 2000 --max-points 120000
```

`--views 12`は水平12方位。上下向きも同じ12方位で撮影し、家具用カメラも加わる。既存フォルダは上書きしない。旧データの`scene.json`を指定すれば、その形式に対応する従来の学習が実行される。新方式への切り替えには新しい出力先での生成が必要。

既存の配置を編集・再利用するときは、保存した`layout.json`の`shapes`を編集し、同じ正面画像を渡す。`min/max`は世界座標、yは下向き。部屋寸法はレイアウト側を使用する。保存済みレイアウトからの生成では深度推定・検出を実行しない。色抽出用の検出座標は出力画像サイズに合わせて拡縮する。

```bash
./run.sh generate --prompt 'A cozy living room' --output runs/livingroom_layout_new --size 384 --views 12 --front-image runs/livingroom_mesh_new/front.png --layout-file runs/livingroom_mesh_new/layout.json
```

床・天井・壁6面の基準平面からのメッシュ頂点のずれは0。参照RGB-D・カメラ整合とPLYの62属性・全ガウス位置も読み直して検証した。自動テストは58件成功。Unityエディター上での操作・描画確認は今回実施していない。

生成データはWSLの`runs/`に保存し、Gitにはコードと文書を保存する。Unityには新しい出力先の`scene_unity.ply`を読み込む。形状は`scene_mesh.glb`または`meshes/*.obj`、参照は`references.jpg`、学習後の比較は`heldout_preview.png`で確認できる。

## 残る制約

- 正面画像からの配置・物体検出は推定。検出されなかった机や見えない家具は追加されない。新規生成例ではソファと棚を検出しており、プロンプト中の机は生成画像に現れていない。
- 部屋は直方体、家具は立体部品の近似。実際の部屋寸法や家具形状の正確な復元ではない。
- 写真的な全周テクスチャ生成は未実装。色・木目・布目と固定照明を使うため、以前の画像生成ベースの外観より単純になる。
- GSの中心・共分散は固定。ガウスの境界のぼけ、細い物体の欠損、壁際の混色は残る。
- 照明は外観へ焼き込まれる。Unityの動的ライトによる再照明には別の材質・レンダラー対応が必要。
- 同じメッシュの未学習カメラは内部整合の検査であり、独立した実写の正解ではない。
