# 配置を共通座標で保持する完成処理 v20

## 目的と入力

初期プロンプトのイメージ、初期画像の構図、同じ家具の大まかな3D配置を維持する。
入力は既存の部屋全体の初期画像と、その画像から構築した物体別メッシュ・共通座標。新しい初期画像や独立した物体T2I画像へ差し替えない。
簡易メッシュは足掛かりであり、木目や画素単位の輪郭を完成形状として固定するものではない。

## 配置と外観の分離

- 背景は共通メッシュと元画像の可視領域に基づく描画として共有し、カメラごとに家具を含む部屋全体を再生成しない。
- 家具の画像領域が壁・床へ混入しないよう、元画像の物体検出領域を建築面への投影から除外する。建築材切り出しに含まれる家具模様も除く。
- AIによる外観更新を、各カメラで投影された物体の可視面と、その周囲の小さな境界帯に限定する。他の物体の画素は変更しない。
- 物体ごとの元画像由来の切り出しを外観条件に使う。微小な可視部分は生成し直さず、同じメッシュから描画する。
- 物体数、ID、位置、向き、カメラは共通のlayout_contract.jsonで保持する。GSの局所形状は既存の自由度を維持し、まとまった移動への弱い罰則も使う。

## 配置の検査

- 生成前後で、変更可能な物体領域以外が書き換わっていないことを数値確認する。
- 画像全体だけでなく家具ごとの深度境界を検査し、欠落・大きなずれの疑いがある画像を不採用にする。深度推定には誤差があり、完全な配置一致の証明ではない。
- 構造面の検査、各家具の移動視点の検査、全計画視点に対する表面被覆の検査を継続する。
- 物体名の検出は別の診断として保存する。ソファの一部がchair、家具の集合がbedと呼ばれる場合があり、このラベルだけを配置変更の証拠にしない。名称の不一致を「解決済み」と偽って報告しない。
- 初期視点は元画像そのものを保持する。元画像と概形の輪郭のずれは引き続き記録され、局所形状や写実性の限界として扱う。

## 実行

```bash
./run.sh synthesize-appearance runs/whole_room_v16_final_20261102_scaffold --output runs/shared_layout_v20_final_20261102 --size 512
./run.sh train runs/shared_layout_v20_final_20261102 --steps 3000 --max-points 180000
```

v18・v19は途中の比較・診断であり、完成版とは扱わない。完成後は実GS描画を確認する。被覆合格と、元画像と同等の画質・家具の正確な形状は区別して報告する。
