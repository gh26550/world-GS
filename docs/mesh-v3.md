# 部品メッシュからの周回参照と3DGS学習

v2では家具の箱形状と面上への強い拘束により、Gaussian形式でも写真を貼った箱のように見えていました。v3は部品を持つ形状と移動カメラによる参照を先に生成します。指定されたliving-room-viewer(2).htmlにはGaussianとカメラがありますが、元の家具メッシュは含まれていません。参照HTMLの形状を抽出・流用した実装ではありません。

## 処理

1. 正面画像と家具検出から、座面・背・肘・脚、楕円天板と4本の脚、棚板・本などを構築。既定の部屋は8×3×8の仮定寸法。
2. 部屋と家具ごとの周回カメラを組み合わせ、家具内に入るカメラを除外。三角形へのレイ交差で可視面を求め、RGB・深度・法線・可視点を取得。
3. 5視点ごとに1視点を評価用に除外し、学習用カメラだけから初期点群を融合。
4. RGB L1、期待深度のlog L1、元表面から離れすぎた場合の柔らかい罰則で学習。位置・回転・3軸スケール・不透明度・SH係数を最適化し、Gaussianの分割・削除を実施。面への強制射影はしない。

交差判定は [trimesh RayMeshIntersector](https://trimesh.org/trimesh.ray.ray_pyembree.html)、分割・削除は [gsplat Strategy](https://docs.gsplat.studio/main/apis/strategy.html) を使用。

評価視点のRGB L1は0.0088〜0.0510、相対深度誤差は約0.50〜3.15%。これは合成メッシュ描画との一致度であり、実際の部屋の再構成精度ではありません。テーブル脚の間を通るレイが奥の壁に届くこと、カメラの移動と姿勢、初期回転などをテストしています。

## 確認するファイル

- `scene_mesh.glb`: 部品と材質を含む生成メッシュ。
- `meshes/object_*.obj`: 家具ごとのメッシュ群。
- `references.jpg`: メッシュから生成した参照画像一覧。
- `scene_unity.ply`: 新しいUnity用GS。既存livingroomのPLYは保持。
- `heldout_preview.png`: 各段の上がメッシュ描画、下が学習したGS。

## 残る課題

家具は検出矩形から作る近似形状で、画像から正確な家具形状を生成するモデルではありません。材質も代表色と手続き的な模様のため、写実性は旧画像投影方式より低下します。今後は物体ごとの画像条件付き3D生成や既存メッシュの導入、形状を保つ多視点の外観生成が必要です。未観測の天井境界などには穴が残ります。今回は「部品メッシュ→移動する多視点→3DGS」の処理を検証した段階です。
