# 配置を維持する多視点生成 v17

## 条件

プロンプト -> 部屋全体の初期画像 -> 全体の簡易メッシュ -> 移動視点の写真参照 -> 3DGS。
初期画像のイメージ・構図、家具の種類と数、大まかな位置・向き・前後関係を維持する。
木目や細かな模様、画素単位の輪郭一致は求めない。簡易メッシュの粗さを完成GSの正解としない。

## 構成

- 部屋と物体別メッシュの共通座標・IDを `layout_contract.json` に保存し、生成途中の配置変更を検出する。
- 各カメラで深度と可視物体IDを描画する。可視領域から、物体ごとの余裕を持った生成領域を作る。
- 背景を生成した後、物体ごとに外観を生成。各処理の変更範囲を制限し、他物体の可視領域を書き換えない。移動視点で元画像の投影画素を永久固定する方法ではない。
- 生成画像の家具を検出し、予想される可視物体と一対一対応を取る。欠落、増殖、種類の変更、大きな位置・大きさの変更を検査する。完全に遮蔽された物体や微小領域はその視点の必須対象にしない。
- 検査は色・模様を使わず、中心位置は画像対角の2%または物体矩形対角の12%の大きい方まで、大きさは概形の0.6〜1.7倍の範囲とする。これらは暫定の工学的しきい値で、同じ入力による比較で調整・検証する必要がある。深度の境界・構造面の検査も継続。不採用画像をGSへ流さない。
- 初期視点は元画像そのもの。元画像であっても配置検査を免除せず、不一致なら概形・画像対応を修正する必要がある。
- GSは既存の局所形状の自由度を残しつつ、同じ物体のGaussianがまとまって移動する変位に追加の弱い罰則を与える。新しい深度推定で各視点の形状を上書きしない。
- 学習前に契約、各参照の配置検査、画像、カメラの記録を確認する。v16のキャッシュをv17として流用しない。

## 実行

```bash
./run.sh generate --prompt 'A cozy living room with a brown sofa, two bookshelves and a wooden coffee table, warm daylight' --output runs/shared_layout_v17 --size 512 --views 24 --seed 52
./run.sh train runs/shared_layout_v17 --steps 3000 --max-points 180000
```

既存の概形を使う比較実験:

```bash
./run.sh synthesize-appearance runs/whole_room_v16_final_20261102_scaffold --output runs/shared_layout_v17_pilot --size 512 --pilot-views 5
```

## 限界

検出器が家具を誤認する場合があり、検査通過は配置の完全一致を証明しない。同種の類似家具の外観上の入れ替えや、向きの変更を画像検出だけで完全には判別できない。遮蔽条件は共通メッシュ由来で、生成画像の遮蔽一致を独立に証明するものではない。
物体領域を分けることで生成回数と計算時間は増える。概形と初期画像に大きな食い違いがあると処理は停止する。これは検査を下げて回避しない。
新規部屋の全視点生成・本学習と、同じ入力によるv16との比較で効果を評価する必要がある。

## 既存v16データでの確認

同じ元画像・概形による初期検査は、左手前の座席をソファの一部とみなす概形と、独立した椅子とみなす検出結果の不一致で停止した。検出器の誤認の可能性もあり、画像・概形の対応確認が必要。検査通過や新方式の画質改善を達成した結果ではない。既存v16の学習結果は変更していない。

領域別生成の2視点診断も実施。主要家具の位置は対応したが、余分な棚・テーブル、別の本棚の未検出があり、両視点とも採用不可と判定した。この診断結果は学習用データにはしていない。配置維持を保証できる画質に達したという結果ではない。
